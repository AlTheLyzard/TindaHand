## Native Android finding

The existing NativeWind flex utility produces flexGrow/flexShrink/flexBasis. These longhands overrode the height-mode KeyboardAvoidingView's flex: 0, leaving the scroll viewport at full height while the IME was open. Native debugging showed a full-height viewport and accumulating bottom displacement; the lower confirmation PIN could not scroll far enough. Padding avoidance bounds the content viewport without that flex conflict. Native scrolling can also interrupt asynchronous geometry measurements, so the controller rechecks after its final scroll event.

Checked the installed Expo SDK 58 documentation and [Expo keyboard guidance](https://docs.expo.dev/guides/keyboard-handling/), React Native TextInput/ScrollView APIs, the installed KeyboardAvoidingView implementation, and Reanimated timing APIs. No dependencies or native build configuration changed.
