## Accessibility error source

`QuickAddModal` renders `CreditorList` in `payables-ui.tsx`. When the creditor list is empty or a search has no matches, its native `Text` previously received the literal `accessibilityRole="status"`. NativeWind passes this accessibility prop through to React Native Text/RCTText. It is not injected by the sheet, a dynamic prop spread, or a dependency. The installed Android `ReactAccessibilityDelegate.AccessibilityRole.fromValue` rejects it because its native role enum has no STATUS entry.

The audit found five direct usages: creditor empty results, payable feedback, payable empty debts, unavailable/settled payable payment, and receivable feedback. All now use `StatusText`: ordinary Text with Android/web polite live-region updates and queued VoiceOver announcements on iOS. No native role cast, error suppression, dependency patch, or global accessibility change is used.

## Shared changes

- `ui/resizable-sheet.tsx`: one height reaction replaces competing reactions; initial measurements settle during native presentation, content/snap changes animate with Reanimated, and keyboard viewport travel follows the existing keyboard host. Handle gestures stay on the UI thread and pause body scrolling/focus reconciliation. Reduced motion, interrupted gestures, safe areas, footer scrolling in constrained space, and accessibility resize actions remain supported.
- `dashboard/quick-add-modal.tsx`: one destination state coordinates customer, creditor, date, and product surfaces. Customer/creditor lists share the original native modal and backdrop. Selecting a creditor changes identity only through `utils/creditor-selection.ts`; empty/stale selections preserve the draft. Selectors have X dismissal and no Back to Debt footer or leftover footer reservation.
- `ui/date-picker.tsx`: selected dates have measured equal width/height and a radius of half that size. Today has an outline only when it is not selected or in the selected range. Selected dates retain the existing primary field ink. `dashboard/quick-add-ui.tsx` uses the same 18-point `calendarDue` asset for expense and debt dates; this raises the expense stroke from 1.6 to 2.6 without changing its touch target.
- `utils/money-input.ts` / `ui/money-input.tsx`: shared strict paste validation, grouping, two decimal places, trailing decimal drafts, blur formatting, caret mapping, deletion, selection replacement, clearing, and external shortcuts. A narrow web selection listener handles RN Web reporting onSelect after a paste. Native platforms keep TextInput selection events. Form values remain ungrouped decimal-peso strings; existing service parsers still produce integer centavos. The adapter documents this integration boundary. Empty stays empty, malformed pastes are rejected, and field-specific zero/minimum/payment/overflow rules remain in existing validators.
- Money adapter integrations: Quick Add and full-page debt/expense/payment fields, POS Cash/GCash/Split/Partial tenders, Add Cash, inventory cost/selling prices, and asset value. Quantities, useful life, PINs, IDs, dates, and references retain their original inputs.
- `ui/confirmation-actions.tsx`: shared full-width stacked primary/destructive action followed by secondary cancellation, token spacing, existing Button dimensions/typography, and a synchronous confirm guard. `confirmation-content.tsx` and `pos-dialog.tsx` use it; explicit row checkout confirmation keeps its established layout. Discard/Keep Editing labels and draft/exit handlers remain caller-owned.
- `pos/product-catalog.tsx`: extracted the existing POS search/suggestions, category scrolling, product grid, ProductTile styling, stock indicators, counts, and alphabet index. POS and `credit-product-browser.tsx` reuse it. Debt browsing owns local snapshots and quantity controls, publishes only on Confirm Products, and never accesses the POS cart or commits a transaction. Back/cancel retains the previously confirmed form selection. The full New Customer Debt route uses this same browser.

Other changed call sites are `inventory/{inventory-ui,product-screen,asset-screen}.tsx`, `payables/{payables-ui,account-balances-screen,payable-payment-screen,creditor-selection-screen}.tsx`, `receivables/receivable-overview-screen.tsx`, `dashboard/add-cash-modal.tsx`, `pos/payment-amount-field.tsx`, and `ui/form-field.tsx`. New regressions are in `tests/money-input.test.cjs` and `tests/creditor-selection.test.cjs`; the existing auth static-render loader now supports the shared input's NativeWind import and checks that peso fields format while quantities/PINs stay unchanged.

No API contract, domain commit rule, dependency, native configuration, or authentication behavior changed. Existing unrelated workspace changes are retained.
