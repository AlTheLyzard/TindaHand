## Scroll-responsive navigation and payment artwork

The next refinement starts navigation at 288 dp, contracts to the existing 256 dp compact width when scrolling down, and expands to 288 dp when scrolling up. Both widths are capped by the available window width with 16 dp side clearance. The bar remains centered, 56 dp high, with fixed 28 dp images, 40 dp active circle and 48×48 dp touch targets. `justify-around` distributes horizontal spacing as the width changes; there are no scaling transforms or backing panel. Existing navigation callbacks, bottom safe-area offset and scroll clearance are preserved.

`use-dashboard-navigation.ts` connects the existing ScrollView's throttled scroll events to `createScrollDirectionTracker` in `src/utils/scroll-direction.ts`. Consecutive movement must accumulate 8 dp in the same direction; reversals reset the accumulated distance. Offsets outside 0…maximum scroll are ignored and reset the measurement baseline so bounce does not reverse navigation. Non-scrollable content and invalid offsets cannot trigger changes. Only a direction that changes the current expanded state updates React state. There is no stop timer or automatic reset: the latest state remains until the next qualifying direction.

`dashboard-navigation.tsx` animates width over 220 ms using the installed Reanimated `withTiming`, quadratic easing and `ReduceMotion.System`. Reduced-motion settings skip interpolation. Width and icon spacing change while images, height and touch areas remain constant. The duration, threshold and expanded size are shared navigation tokens.

The previous payment disk was embedded in the raster. The row now uses `payment-symbol.png`, extracted from the same approved hand/coins glyph on the background-free icon sticker sheet with transparent alpha. ## Upward spring animation refinement

Only navigation motion is refined in this follow-up. Compact remains 256 dp; the upward target grows from 288 to 312 dp, capped at window width minus 32 dp. The bar lifts 6 dp as it expands. Width and lift share one Reanimated progress value: upward uses `withSpring` (mass 0.6, stiffness 520, damping 32, overshoot clamped); downward keeps the existing 220 ms eased `withTiming` contraction. Neither transition scales icons, labels, touch targets or bar height. Initial expanded state, centered placement, colors, active indicator, items and callbacks are unchanged.

The existing 8 dp direction threshold, bounce filtering, and same-target state guard remain untouched. Direction reversals retarget the running shared progress without resetting to an endpoint or cancelling/restarting on repeated same-direction scroll events. Stopping scroll retains the latest target. Both spring and timing use `ReduceMotion.System`, so reduced-motion settings skip interpolation. No full-width background or new shadow is added.

The screen's reserved bottom scroll padding increases by exactly the 6 dp lift to retain content clearance in the higher state. Bottom safe-area placement remains inset + 8 dp, with the expanded visual bar another 6 dp above that.
