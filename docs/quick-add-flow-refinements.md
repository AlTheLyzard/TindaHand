# Quick Add flow refinements

Scope: Add Customer Debt, Add Store Debt, and Record Expense from the dashboard FAB.

Read root AGENTS.md, the SDK 58 package/configuration and npm lockfile, requirements engineering, and workbook MA-QA-001/004/005, MA-AR-002, MA-AP-002, KH-QA-001/003 and KH-AR-002 before implementation. The named role sheets remain the baseline. The copy owner sheet proposes removing Store Debt from Quick Add and replaces its required-information validation criterion with a cancel action. These conflicts were not merged; this request explicitly retains all three existing flows and their validation. Requirements files remain unchanged.

## Files and behavior

- `src/components/ui/resizable-sheet.tsx` and `src/utils/sheet.ts`: retain the shared measured-content, compact and expanded snap points. Replace JS-thread PanResponder/Animated height tracking with the installed Gesture Handler 3/Reanimated APIs. The handle activates immediately and tracks absolute screen coordinates on the UI thread, including activation and subsequent updates. Starting another drag cancels the active snap animation. Layout changes during a drag rebase its origin; cancellation restores the selected snap. Release velocity is converted from points/second to the existing utility's points/millisecond. Downward dismissal still invokes draft protection. The scroll body owns content scrolling and keyboard dismissal; actions stay pinned when space permits and scroll with the fields in very limited space. Existing safe-area and keyboard avoidance remain.
- `src/components/dashboard/quick-add-modal.tsx`: keep customer/creditor selection as sheets in the same native modal window, with the underlying draft mounted and inaccessible while a picker is active. Picker dismissal retains the selection; choosing a row updates only its identity/name. Existing new-name actions use the shared primary Button. Back handling still closes the topmost picker/calendar/confirmation first. The modal has its own GestureHandlerRootView, as required for gestures inside native modal content. Both Due Date actions use the existing CalendarPicker without changing its appearance; manual date input and expense date selection remain available.
- `src/components/receivables/receivables-ui.tsx` and `src/components/payables/payables-ui.tsx`: suppress the soft keyboard when name-field focus opens the selection sheet. Manual entry still permits the keyboard.
- `src/components/dashboard/quick-add-success.tsx`: compact centered content for Debt Saved, Store Debt Saved and Expense Recorded, using the existing typography, success colors, check icon and primary Done button. Only the formatted peso amount uses Text Primary; surrounding text keeps Text Secondary. Redundant descriptions are removed. Only the outer ring scales/fades, with a gentle 3.6-second cycle. The host owns animation cancellation, including during retained modal exit content, and subscribes to the existing live reduced-motion preference.
- `src/components/dashboard/quick-add-modal.tsx`: successful save animates the entry sheet away before presenting centered success content in the same native modal/backdrop. No second native window or success backdrop is added. The existing synchronous busy lock, service token, validation, failure handling and data updates remain; saved/exiting forms cannot resubmit. Done, backdrop and Back/Escape close success.
- `src/components/dashboard/quick-add-ui.tsx`, `src/constants/pos-icon-assets.ts`, `scripts/prepare-pos-icons.cjs`, `assets/images/pos/calendarDue.svg` and `calendarDue-active.svg`: reproducible due-date-specific calendar assets with strokes increased from 1.6 to 2.6 (active 2.2 to 3.2). The 18-point size, geometry, button tint, alignment and touch target are preserved. Other calendar icons retain their existing stroke.

No dependencies, domain services, seed fixtures, route configuration or native build configuration changed.
